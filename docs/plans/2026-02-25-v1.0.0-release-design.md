# v1.0.0 Production Release Design

**Date**: 2026-02-25
**Current Version**: 0.3.3
**Target**: First production-ready release

---

## Current State Assessment

### What's Complete
- 8/8 hardening plugins (kernel, SSH, firewall, PAM, services, audit, permissions, MAC)
- Full CLI + GUI (Tauri/Leptos) with feature parity
- Checkpoint system with Ed25519-signed snapshots + rollback
- 5-distro validation (Arch, Debian, Fedora, Rocky, openSUSE) — 100% pass
- 6 compliance frameworks (CIS, STIG, NIST, PCI-DSS, HIPAA, GDPR)
- Report generation (text, JSON, CSV, HTML, PDF)
- Remote SSH scanning
- Scheduled scanning with email/webhook notifications
- 418+ unit tests + 84 GUI tests + 123 cross-distro tests
- Codebase audit: 113 files, 93 fixes, clippy clean

### What's Missing for v1.0.0
The gap between 0.3.3 and 1.0.0 is **operational maturity**, not features.

## Release Criteria

### Must-Have (Blocking)

| Item | Rationale | Effort |
|------|-----------|--------|
| **Distribution packages** (AUR, deb, rpm) | Users can't install without packages | Medium |
| **Systemd unit files** in repo | Required for packaging + scheduled scanning | Small |
| **Man page** (`hardener.1`) | Standard for CLI tools in packages | Small |
| **Default config file** with comments | Users need a starting point | Small |
| **Install/upgrade documentation** | End-user guide for each distro | Medium |
| **Security policy** review | Verify SECURITY.md is complete and accurate | Small |

### Should-Have (High Value)

| Item | Rationale | Effort |
|------|-----------|--------|
| **Integration test suite** for packages | Verify install → scan → apply → rollback on fresh systems | Medium |
| **Polkit policy file** | Nicer authentication dialogs instead of raw pkexec | Small |
| **AppImage build** | Universal Linux binary for users without package manager | Small |
| **WCAG AA contrast audit** | Accessibility compliance for the GUI | Small |
| **Error recovery documentation** | What to do when hardening goes wrong | Small |

### Nice-to-Have (Defer if Needed)

| Item | Rationale | Effort |
|------|-----------|--------|
| High Contrast theme (WCAG AAA) | Accessibility for low-vision users | Medium |
| Shell completions (bash, zsh, fish) | Developer experience | Small |
| Configuration management integration docs | Ansible/Puppet/Salt examples | Medium |
| Internationalisation (i18n) | Non-English users | Large — defer to v1.1+ |

## Architecture for v1.0.0

No architectural changes needed. The codebase is stable and well-structured:

```
[User] → CLI (hardener) → Core Engine → Plugins → System
         │                                  ↑
         GUI (Tauri) → pkexec → CLI ─────────┘
         │
         Scheduler (daemon/timer) → CLI
```

### New Files to Create


## Version Bump Strategy

### Semantic Versioning
- 0.3.3 → 1.0.0 (major bump signals production readiness)
- No breaking API changes needed — it's a maturity signal

### Cargo.toml Changes
- Root `version = "1.0.0"`
- All workspace members inherit via `workspace = true`
- `tauri.conf.json` version updated
- MSRV documented (Rust 1.85+)

## Release Checklist

### Phase 1: Infrastructure (Pre-Release)
- [ ] Create `systemd/` directory with service + timer units
- [ ] Create `data/linux-hardener.desktop` file
- [ ] Create `data/config.toml.example` with commented defaults
- [ ] Create `man/hardener.1` man page (or generate from CLI help)
- [ ] Create `packaging/` directory with AUR/RPM/DEB specs

### Phase 2: Quality (Pre-Release)
- [ ] Apply test quality fixes (see `2026-02-25-test-quality-fixes.md`)
- [ ] Review SECURITY.md for completeness
- [ ] Write install/upgrade guide for each distro family
- [ ] Run full cross-distro validation one final time
- [ ] Verify musl binary works on all 5 distros

### Phase 3: Packaging (Pre-Release)
- [ ] Build and test AUR package locally with `makepkg`
- [ ] Build and test .deb with `dpkg-buildpackage` or `cargo-deb`
- [ ] Build and test .rpm with `rpmbuild`
- [ ] Test install → scan → apply → rollback cycle from each package

### Phase 4: Release
- [ ] Version bump all Cargo.toml + tauri.conf.json to 1.0.0
- [ ] Update CHANGELOG.md with v1.0.0 release notes
- [ ] Update ROADMAP.md to reflect v1.0.0 completion
- [ ] Tag release: `git tag -a v1.0.0 -m "v1.0.0: Production release"`
- [ ] Create GitHub release with binary assets
- [ ] Submit AUR package
- [ ] Upload to PPA (Ubuntu) / COPR (Fedora)

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| Packaging breaks on specific distro | Medium | High | Test on all 5 before release |
| Systemd unit doesn't start correctly | Low | Medium | Test in nspawn containers |
| Config file path mismatch | Low | High | Verify all path constants match packaging |
| Missing runtime dependency | Medium | Medium | Test fresh installs (not dev machines) |
| GUI needs webkit version not in stable repos | Low | High | Document minimum distro versions |
